# Spec 10 — Agent evals

**Label:** `evals` · **Status:** ☐ todo
**Depends on:** [09 specialized agents](09-specialized-agents.md)

## Goal

A deterministic, verifiable test suite for every agent in [09](09-specialized-agents.md), so
"the agent is working as intended" is a measured claim rather than an impression — and so
alignment to the objectives in this backlog can be re-checked after every change to a prompt,
a model, or the engine.

Without this, the agent roster is unfalsifiable and drifts silently.

## The two principles

### 1. Plant and recover

Take the logic from the vault's own methodology. q21's capacity certificate plants an effect
of known size and requires the probe to recover it; a null is only reportable once the
detection floor is measured. Same shape here: **plant known defects in a fixture, then measure
recovery.**

Measure **both directions**. "Did it find things" is not a result — the pair that matters is:

- **recall** — of N planted defects, how many were found
- **precision** — how many findings were invented

An agent that reports 20 findings on a vault with 5 planted defects has failed, however many
it caught.

### 2. Assert on the artifact, not the transcript

Every agent here produces a file the engine already parses. `crux validate` and
`engine.snapshot` are therefore **free deterministic oracles**. Never grade an agent on what it
said; grade it on what the engine reads back.

### Anti-tautology (from the `tdd` skill)

> *"Expected values must come from an independent source of truth."*

Applied here: **the planted defects must be authored independently of the agent that finds
them.** A fixture generated by the same agent under test, or by the same prompt lineage, grades
itself. Fixtures are committed, hand-authored, and reviewed — not generated on the fly.

This mirrors [09](09-specialized-agents.md)'s whole argument one level up: the thing that
writes the test must not be the thing that writes the answer.

## Harness

The pattern already exists and should be reused, not rebuilt. `selftest.py` builds a dummy
vault and asserts every invariant — roll-up, gate, idempotency, integrity, CLI help — with no
GPU, no tokens, no SLURM. The `evolve-crux` gate already requires selftest green **with a grown
assert count**.

Agent evals are the same harness pointed at a different target. The distinction to preserve:
engine asserts are fully deterministic and run in CI; agent evals invoke a model and therefore
need a separate command and a tolerance band.

## Per-agent fixtures

| agent | fixture | assertion | ground truth? |
|---|---|---|---|
| `crux-audit` | vault with **N planted defects** — over-cap node, orphan task, dangling artifact, gate backlog, dependency cycle | finds exactly N, invents 0 | **yes** — cleanest eval of the set |
| `crux-close` | hypothesis + canned results directory where the correct tick pattern is **known by construction** | derived verdict matches the known verdict | **yes** |
| `crux-null` | hypothesis whose boring explanation is planted (e.g. the with-`c` arm simply has more capacity) | names the planted confound family | **yes** |
| `crux-verifiables` | h59's real 11-verifiable node, stripped to its claim + null | returns materially fewer; every one carries a distinct failure scenario; ≥1 discriminates against the null | partial — count is a proxy, the filter checks are hard |
| `crux-critic` | drafts at 200 / 600 / 2000 words; one genuinely-single question vs one that is three | rejects the right ones, passes the good one | partial |
| `crux-migrate` | fixture repo with known content | seed parses; node count within a band; every `[x]` tick carries an evidence pointer that resolves | partial — band, not exact |
| `crux-tests` | a requirement plus a deliberately non-compliant implementation | the generated tests fail against it | **yes** — the strongest available |

**Label the proxies as proxies.** `crux-audit`, `crux-close`, `crux-null` and `crux-tests` have
genuine ground truth. The rest are proxies and should be reported as such rather than dressed
up — an eval that overstates its own rigour is the same failure mode this whole backlog exists
to fix.

## Design notes

- **Fixtures are committed vaults**, small and hand-authored, living under the scaffold beside
  `selftest.py`.
- **Non-determinism is handled by banding, not by hoping.** Run each eval K times; report the
  distribution. A pass is "recall ≥ X and precision ≥ Y across K runs," not one lucky run.
- **A failing eval is a defect in the agent, not in the fixture.** Editing a fixture to make an
  eval pass is the research equivalent of moving the goalposts, and it is exactly what
  pre-registration exists to prevent. Fixtures change only when the *spec* changes.
- **Cost.** These invoke models, so they do not belong in the per-commit CI that runs
  `selftest.py`. Separate command, run on agent or prompt changes.

## Rejected alternatives

- **Grading on transcripts / LLM-as-judge over agent output.** The engine already parses every
  artifact these agents produce; a judge model would add nondeterminism where a parser gives
  certainty. Reserve judging for the proxy cases where nothing parseable exists.
- **Generating fixtures with the agent under test.** Self-grading — the tautology the `tdd`
  rule names.
- **Recall-only scoring.** An agent optimizing recall alone learns to report everything.

## Open questions

- K, and the pass bands per agent.
- Whether agent evals gate a PR (the `evolve-crux` gate is currently deterministic-only and
  runs in CI; adding a model-invoking step changes that contract).
- Whether fixture vaults live in the crux repo or a sibling, given they will accumulate.

## Acceptance criteria

- Every agent in [09](09-specialized-agents.md) has at least one fixture and a stated pass band.
- The runner reports precision and recall separately, and never reports a proxy as ground truth.
- Planted-defect fixtures are hand-authored and committed; no fixture is generated by an agent
  under test.
- A deliberately degraded agent prompt fails its eval — i.e. the suite can actually detect
  regression.
