# audit-01 — seven defects, planted on purpose

`crux-audit`'s whole job is to drive the deterministic checks and report what they find. That
makes it the cleanest eval in spec 10's set: every defect below is an id the engine already
emits, so the ground truth is exact set arithmetic rather than a judgment.

**Hand-authored.** The vault was built with the ordinary `crux` verbs — so every derived field
(question status, the ledger, the hash-lock) is the engine's own — and the defects were then
planted one at a time, each in its own node. Nothing here was generated by `crux-audit` or by
anything sharing its prompt lineage.

**`checks:` above is explicit and load-bearing.** `gate` is an *opt-in* check: a plain
`crux validate` never runs it. A certifier using the default check set would decide this
fixture contains no gate backlog, and would then score a correct finding on `q2` as an
invention — precision 0.0 for the right answer.

## Planted

| id | tier | class | what was planted, and how |
|---|---|---|---|
| `q2` | warning | gate:backlog | `h1` was run and closed, so `q2` derives into `review`; no synthesis was ever drafted for it. The status is the engine's, not a hand-set field. |
| `q3` | warning | economy:over-cap | 942 words pasted into `## Question`, against the 400-word `PROSE_CAP`. |
| `h2` | problem | artifact:missing | `## Artifacts` links `results/h2/report.md`, which is not on disk. |
| `q4` | problem | tree:parent-cycle | `q4.parent = q5`. |
| `q5` | problem | tree:parent-cycle | `q5.parent = q4`. One planted cycle, two emitted ids — the check reports per node, and each id carries exactly one defect. |
| `t2` | problem | task:dangling-ref | `refs: h404`, a hypothesis that is not in this vault. |
| `wiki:detection-floor` | problem | wiki:orphan | a page no tree node and no other page links to. |

The `class` column is for the reader. **Nothing parses it** — deliberately, so that adding a
class cannot quietly become a schema.

## What is *not* planted here

- **No scientific judgment.** Every defect above is structural. A stale answer — *"q4's answer
  predates six findings that cite it"* — is a research judgment on the footing of `answer` and
  `pursue`, PI-gated one node at a time, and `crux-audit`'s own definition excludes it. Grading
  an agent on recovering one would make staleness a deterministic predicate by fiat.
- **No task dependency cycle.** Spec 10's defect list says "dependency cycle" without saying
  which. A task `blocked_by` cycle is reported as the *status* `blocked` and never reaches
  `problems`, so it has no id to score against. A parent cycle is the plantable one, and that
  is what `q4` and `q5` carry.

## Reading the eval

An agent that reports all seven ids and nothing else scores recall 1.0 and precision 1.0. An
agent that reports twenty findings on a seven-defect vault has failed, however many it caught —
which is why precision is scored at all.

`band: unset`. The pass bar is a pre-registered bar and bars are the PI's; one invented with no
measurement behind it is a guess with a decimal point. Until it is set, this fixture reports its
distribution and claims no pass.
