### concept

- [[adaptive-sorting\|Adaptive sorting]] — An adaptive algorithm changes its behavior based on the structure of the input, like whether data is already partially sorted.
- [[average-case-analysis\|Average case]] — Average case analysis predicts how an algorithm performs on typical, randomly distributed input data.
- [[background-load\|Background load]] — Other programs running on your laptop steal CPU and memory time, making your code slower in unpredictable ways.
- [[best-case-worst-case\|Best case and worst case]] — Every algorithm behaves differently depending on the input. Best case is when input cooperates, worst case is when it does not.
- [[big-o-notation\|Big-O notation]] — Big-O notation describes how the time or space requirements of an algorithm grow with input size.
- [[cache-locality\|Cache locality]] — The CPU is much faster at reading data that is close together in memory than data scattered all over the place.
- [[comparison-count\|Counting comparisons]] — Counting comparisons is a way to measure algorithm efficiency without running code or assuming a specific computer.
- [[crossover-points\|Crossover points]] — A crossover point is the input size where one algorithm becomes faster than another.
- [[extrapolation-risks\|Predicting past your data]] — Guessing performance at sizes you never tested is risky because patterns change outside the tested range.
- [[garbage-collection-pauses\|Garbage-collection pauses]] — Languages that automatically clean up memory can suddenly pause code to sweep away garbage, making some runs much slower.
- [[growth-rate-curves\|Growth-rate curves]] — Growth-rate curves are graphs showing how an algorithm's runtime increases as input size grows.
- [[interpreter-overhead\|Interpreter overhead]] — The cost of the language interpreter or runtime environment, which executes your code line by line or translates it on the fly.
- [[jit-compilation\|Just-in-time compiling]] — Translating code from a slower interpreted form to a faster machine-like form while the program runs, learning from patterns.
- [[memory-allocation\|Memory allocation]] — Requesting new memory from the operating system is slow and unpredictable, adding hidden cost to code.
- [[micro-benchmarking-pitfalls\|Micro-benchmark pitfalls]] — Six traps that catch people when they try to time code and six ways to avoid each one.
- [[monotonic-clocks\|Monotonic clocks]] — A monotonic clock never runs backwards and measures elapsed time reliably, unlike system clocks that can jump.
- [[pivot-choice\|Choosing a pivot]] — The decision of which item to use as the pivot in quick sort, which can make the sort much faster or slower.
- [[power-management\|Power management]] — Battery and power settings make the CPU run slower or faster, changing how long code takes to run.
- [[recursion-depth\|Recursion depth]] — Functions that call themselves use memory for each call, and calling very deeply can cause the program to crash.
- [[run-detection\|Finding runs]] — Run detection identifies stretches of data that are already sorted, then uses them to speed up sorting.
- [[stability\|Stability]] — A stable sort preserves the original order of items that compare equal.
- [[thermal-throttling\|Thermal throttling]] — When a laptop gets too hot, it automatically slows down to protect the hardware, making later runs slower than earlier ones.
- [[timer-resolution\|Timer resolution]] — Timer resolution is the smallest time interval a computer's clock can measure, limiting measurement precision.
- [[wall-clock-time\|Wall-clock time]] — Wall-clock time is the real elapsed time between when a program starts and when it finishes.
- [[warm-up-effects\|Warm-up effects]] — The first run of code is often much slower than the second and third because the system is not ready yet.

### dataset

- [[duplicate-heavy-input\|Duplicate-heavy input]] — A test list where many items have the same value, not all different as most algorithm examples assume.
- [[nearly-sorted-input\|Nearly-sorted input]] — A test list where most items are in order but a few are out of place, like real data after one round of mixing.
- [[random-permutations\|Random permutations]] — A test list where the items are in random order, with every position equally likely to have any value.
- [[reverse-sorted-input\|Reverse-sorted input]] — A test list where items are in order from largest to smallest, the opposite of what the sort expects.
- [[sorted-input\|Already-sorted input]] — A test list where items are already in order from smallest to largest.

### method

- [[bubble-sort\|Bubble sort]] — Bubble sort repeatedly compares neighboring items and swaps them until everything is sorted.
- [[bucket-sort\|Bucket sort]] — Bucket sort distributes items into buckets, sorts each bucket, then concatenates the results.
- [[counting-sort\|Counting sort]] — Counting sort counts how many items have each value, then reconstructs the sorted list from these counts.
- [[curve-fitting-basics\|Fitting a curve]] — Drawing a line or curve through data points to guess a formula that predicts performance at sizes you have not tested.
- [[doubling-experiments\|Doubling experiments]] — A doubling experiment repeatedly measures an algorithm on lists twice as large, revealing the growth pattern.
- [[heap-sort\|Heap sort]] — Heap sort uses a data structure called a heap to sort by repeatedly extracting the smallest item.
- [[hybrid-sorts\|Hybrid sorts]] — Hybrid sorts combine multiple sorting strategies, switching between them based on data size or other conditions.
- [[input-generators\|Input generators]] — Programs that create lists for testing, choosing what kind of list to make based on the test design.
- [[insertion-sort\|Insertion sort]] — Insertion sort builds a sorted list one item at a time, like sorting playing cards in your hand.
- [[median-of-three\|Median of three]] — A technique to find a pivot for quick sort by comparing three items and using the one that is neither smallest nor largest.
- [[median-vs-mean\|Median or mean]] — Using the middle value instead of the average to describe typical performance when one slow run throws off the average.
- [[merge-sort\|Merge sort]] — Merge sort divides a list in half recursively, then merges the sorted halves back together.
- [[outlier-trimming\|Trimming outliers]] — Removing the slowest and fastest times to ignore random bad luck before calculating a summary.
- [[quick-sort\|Quick sort]] — Quick sort picks a pivot item and partitions the list around it, then recursively sorts the partitions.
- [[radix-sort\|Radix sort]] — Radix sort sorts numbers by examining one digit at a time, from least significant to most significant.
- [[repeated-trials\|Repeated trials]] — Running the same code multiple times and collecting all the times to reduce random noise.
- [[seeded-randomness\|Seeded randomness]] — Using a fixed seed to make a random list the same every time you create it, so tests are repeatable.
- [[selection-sort\|Selection sort]] — Selection sort finds the smallest unsorted item and moves it to the front, repeatedly.
- [[three-way-partition\|Three-way split]] — Dividing a list into three groups: items less than the pivot, items equal to the pivot, and items greater than the pivot.
- [[timsort\|Timsort]] — Timsort is a hybrid algorithm combining merge sort and insertion sort, designed to handle partially sorted real-world data efficiently.
