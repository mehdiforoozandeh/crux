# PRD: 16.2 — science voice, enforced at chat time

- **Kind:** fix
- **Spec:** [.spec/16-science-voice.md](../../.spec/16-science-voice.md) (follow-up to
  [PRD 16.1](16.1-science-voice.md), which landed the rules)

## Problem / motivation

The PI has reported the invisible-notebook requirement failing in live sessions **twice**,
most recently naming task ids (`t81`) appearing in conversation. Spec 16 landed the rules
and the lint; neither is holding. Two causes, both findable in the code.

**1 · `skills/crux/SKILL.md` contradicts itself, and the contradiction wins.** Voice rule 2
says bookkeeping is silent: *"Opening questions, writing hypotheses, opening and closing
tasks, updating findings — do it and say nothing."* But `○ = act-and-report` appears five
times over exactly those verbs — at lines 141, 184, 313, 317 and 319. The `○`/`◆` glyph was
written for the **signature** axis (*do I need the PI's yes?*); spec 16 introduced a second,
independent **disclosure** axis (*do I say anything?*); the two collapsed onto one symbol. So
the agent files a task, reads "report it", and reports it — with the only handle it has,
`t81`. The observed symptom is produced on purpose by the file that forbids it.

**2 · Nothing checks the voice at chat time.** `voice_lint` is correct and complete
(`engine.py`), and its own comment states the gap: *"nothing here runs at chat time. Its
consumers are the persona eval and selftest."* So it grades shipped fixtures in CI and never
a live conversation, while every few turns the CLI hands the agent a fresh `✓ t81
(tasks/t81_….md)` receipt. Recent text beats a rule read once, 190 lines into a 517-line
file. Spec 16 argued the modeled dialogues would bind; the dialogues were cleaned in 16.1 and
the leak survived, which refutes that.

## Design decision

Three changes, one per mechanism — the pressure, the handle, the measurement.

**A · Split the disclosure axis from the signature axis in SKILL.md.** `○`/`◆` keeps meaning
signature-or-not, and gains an explicit denial of the second reading: acting without asking
is not acting with an announcement. The phrase **"act-and-report" is deleted** wherever it
covers bookkeeping — it is the instruction that produces the leak. The Voice section moves
**above** every `○` occurrence, so the rule is read before the table that used to contradict
it.

**B · Hand over the replacement handle where the id is minted.** Every id-minting verb
(`ask`, `hypothesize`, `task add`, `synthesize`, `rd`) prints one extra line naming the
chat-safe handle and marking the id as notebook-side. The agent reaches for the id partly
because it needs *a* handle and the id is the nearest one in context; supplying the
substitute at that moment is stronger than a prohibition 200 lines away. This is the
always-on half.

**C · Run `voice_lint` at chat time.** A new `crux voice` verb reads a Claude Code hook
payload on stdin, parses the session transcript into `(pi, agent)` turns, runs the existing
`voice_lint` against the vault's agreed glossary, and returns any finding **on the newest
agent turn** as hook `additionalContext`. Registered as a `PostToolUse` hook by
`install.sh`, idempotently, and checked by `crux doctor`. This is the detection half.

**Rejected: relying on a stricter prose rule alone.** That is what 16.1 did, and the PI's
second report is the evidence it does not hold.

**Rejected: making the CLI stop printing ids.** The CLI is declared agent-facing by spec 16
and the agent needs the id to run the next command. B re-frames the receipt instead of
removing what the agent depends on.

## Scope — what this does not do

- **A hook cannot un-send a message.** Claude Code exposes no interception point between the
  agent composing PI-facing text and the PI reading it, so C detects and corrects; it cannot
  prevent the first leak of a session. B is the preventive half; C stops the *repetition*
  and makes live drift visible instead of silent.
- No change to `voice_lint`'s semantics, `CRUX_LEXICON`, or `NODE_ID_RE`.
- No change to the cockpit, which keeps its id badges by ruling.
- The other `crux-*` agents keep ids in their reports; the rules still bind at the relay
  point.

## Acceptance criteria

- [x] `skills/crux/SKILL.md` contains no occurrence of "act-and-report", and no instruction
      to report routine bookkeeping.
- [x] The Voice section appears **before** the first `○` in SKILL.md.
- [x] The `○` legend explicitly states that acting without asking is not announcing.
- [x] `crux ask`, `crux hypothesize`, `crux task add`, `crux synthesize` and `crux rd` each
      print the node title and a chat-safe-handle marker beside the minted id.
- [x] The added receipt line carries no second-person address (holds `run_cli_third_person`).
- [x] `crux voice --turns <json>` reports a leaked id and a leaked lexicon term, and is
      silent on a clean conversation.
- [x] `crux voice --hook` parses a Claude Code JSONL transcript into turns, counting only
      real chat text — **tool-use and tool-result blocks are excluded**, since a tool result
      full of ids is not the PI speaking.
- [x] `crux voice --hook` reports only findings on the newest agent turn, so one old leak is
      not re-reported on every later tool call.
- [x] `crux voice --hook` exits 0 and emits nothing on a malformed payload, a missing
      transcript, or any internal error — a hook that breaks a session is worse than a leak.
- [x] `crux voice --hook` is silent when the tool call it fired on was not a crux command.
- [x] The PI's agreed glossary terms are licensed from turn zero.
- [x] `crux voice --install-hook --settings <path>` merges the `PostToolUse` entry
      idempotently: running it twice yields one entry, and unrelated settings survive.
- [x] `crux doctor` reports the hook's presence, and warns (never fails) when it is absent.
- [x] `install.sh` registers the hook and reports what it did.

## Backward-compat / migration

**No vault-format change**, and no change to verdict, roll-up or view logic — the new verb is
read-only and the other edits are prose and one extra output line. `ENGINE_VERSION` is
therefore **not** bumped and there is **no migration**. Gate 3 (existing vaults still load)
applies unchanged.
