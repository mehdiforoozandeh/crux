# PRD: fetch and ingest the picked candidates

- **Kind:** feature · **Spec:** [.spec/17-openalex.md](../../.spec/17-openalex.md) (slice 17.4, closes the epic)

## Problem / motivation

The loop worked except for its last step: the PI read `candidates.tsv`, decided, then
hand-downloaded each PDF and hand-typed an ingest line. The list already carries the
open-access PDF url for every row, so that step is clerical.

## Design decision

One verb: `crux lit fetch <slug> --pick W… --pick W…`.

**Ticking is the argument list, not a file.** The agent shows the top 30, the PI says which,
the agent passes them as `--pick`. A `picks.md` mirroring `scope.md` was rejected: the record
of what was taken already exists in `raw/` and the registry, so a second file is bookkeeping
with no reader. A marker column in `candidates.tsv` is worse — that file regenerates.

**Filenames** are `<year>-<surname>-<three title words>.pdf`, derived from the cached record,
with a numeric suffix on collision. Readable in a file listing, which a bare work id is not.

**After a successful download** the file is ingested with the canonical title and work id from
the same record.

## Safety — the load-bearing part

This is the only place crux writes bytes from the internet into the PI's curated directory,
and everything the wiki claims traces back to a file there. So:

- The body must begin with `%PDF` or it is refused and discarded. Without this an HTML login
  wall served with a 200 lands in `raw/` named `.pdf`, gets hashed, and is compiled into the
  wiki as though it were the paper. **This fired on the first real run** — PMC served HTML
  with a 200 for a listed open-access PDF.
- A 50 MB cap, checked against `Content-Length` before reading and against the body after.
- **No placeholder file, ever.** A paper crux cannot get is reported with its DOI and nothing
  is written. This resolves the spec's second open question.
- No scraping and no paywall circumvention. A publisher that refuses a non-browser agent is
  reported as such; pretending to be a browser to get past it is circumvention, and crux says
  so and lets the PI fetch it themselves.

## Two deviations from the approved PRD, both from the first real run

1. **A per-pick failure is reported, not raised.** The PRD had a non-PDF response raise. On
   the first real fetch, two of three picks came back 403 from their publishers — with a raise
   one gated host sinks a ten-pick run. Failures are now one row each with a reason, the run
   continues, and the CLI exits 1 if any failed. "Nothing is written to `raw/`" is unchanged.
2. **The skill's size bar became an absolute 130-line cap** rather than "under
   `crux-autopilot/SKILL.md`". That bar was a proxy for "not bloated", written when this skill
   covered one flow; it now documents three verbs autopilot has no equivalent of, and beating
   the comparison would have cost the fetch section rather than any fat. It sits at 116.

## Scope — what this does not do

No retry, no parallel downloads, no resume. No wiki page compilation — that stays the agent's
job, as everywhere in `crux-wiki`.

## Acceptance criteria

- [x] An open-access pick downloads, lands under the derived filename, and is ingested with
      the canonical title and work id.
- [x] The fetch lookup asks for `authorships`. (Found by the manual criterion: `CAND_SELECT`
      omitted it, so the first real fetch filed `2021-unknown-…` with an author-less title —
      the exact failure 17.1 exists to prevent.)
- [x] A response not beginning with `%PDF` is refused and reported; nothing reaches `raw/`.
- [x] A publisher refusing the request is reported against that pick alone.
- [x] A download over the 50 MB cap is refused; nothing reaches `raw/`.
- [x] A pick with no open-access url is reported with its DOI, writes nothing, and the other
      picks in the same run still land.
- [x] A pick already in the registry is skipped, not re-downloaded.
- [x] A filename collision takes a suffix rather than overwriting.
- [x] `engine.py` imports no `urllib`; selftest green and offline from a fresh clone with no
      key (2083 → 2096).
- [x] (manual) Fetched real papers from the chromatin candidate list.
      `2021-libbrecht-segmentation-and-genome.pdf` landed at 1.4 MB, starts `%PDF-1.6`, and is
      registered as *"Segmentation and genome annotation algorithms … — Maxwell W. Libbrecht,
      Rachel C.W. Chan, Michael M. Hoffman (2021)"*. Three other picks were correctly refused:
      two publisher 403s and one PMC HTML-with-200.
