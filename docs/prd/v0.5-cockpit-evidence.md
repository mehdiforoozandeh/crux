# PRD: v0.5.0 — evidence artifacts, the synthesis close-gate, and a cockpit you can actually read in

- **Kind:** feature (batch) — **Roadmap:** Epic 1 `ui` (node detail, review gate), plus engine/CLI work outside any epic
- **Release:** `v0.5.0` · **ENGINE_VERSION:** `1.1` → `1.2` (vault semantics change: `## Artifacts`, the question close-gate)

## Problem / motivation

Eleven things, one release. They fall into three groups:

**1 · Evidence is invisible.** A hypothesis records a verdict and a metric, but the actual
output of the experiment — the report, the figures, the tables — lives somewhere else
entirely and the vault never points at it. The cockpit can't show it because nothing links
it, and even the markdown crux *does* hold (findings, problem statements, answers) is
printed as literal source in the right panel: `**bold**`, `- bullets`, `## headings` all
raw. The one place that renders markdown properly is the Wiki reader.

**2 · A question can close on nothing.** `crux answer q3` flips a question to `resolved`
with an optional free-text line. There is no artifact that says *this is what we concluded
and here is the human who signed it*. The review gate trips, and then the trail stops.

**3 · The cockpit fights you.** No colour for `inconclusive` in the legend (the verdict
exists in the engine's vocabulary and on the nodes — just not in the key). Neither panel
can go full-screen. The search box is 230px. "Focus" only means "collapse non-open
questions" — you can't say *show me q3 and nothing else*. The tree twitches at rest. The
browser tab says "crux cockpit" no matter which project you're in. And nothing tells you a
newer crux exists.

## Design decisions

### A · Cockpit tab title
`document.title = "crux cockpit: " + project.title`, set on every snapshot. The static
`<title>` in `index.html` stays as the pre-snapshot fallback.

### B · Legend = the engine's full vocabulary
`inconclusive` is already in `VERDICTS` and already has `--v-inconclusive` in both themes
and an `.h-inconclusive` fill rule — it was simply missing from the `LEGEND` table, along
with `idea` and `staged`. Fix: the legend lists **every** state `statusClass()` can return
— questions `open · review · resolved`; hypotheses `idea · staged · running · supported ·
partial · refuted · inconclusive`. A selftest derives the expected key set from
`QUESTION_STATUS` / `IDEA_STATUS` / `VERDICTS` and fails if the legend drifts from the
engine again.

### C · Artifacts: link the report, render the report
**Convention.** Result files live under `results/<hid>/` inside the vault (sibling of
`raw/` and `wiki/`). A hypothesis links them from a new `## Artifacts` section:

```markdown
## Artifacts

- [Full report](results/h1/report.md)
- results/h1/ade20k-miou.png
- results/h1/per-seed.csv
```

Both forms parse: `[label](path)` and a bare path. Paths are **vault-relative**; an
absolute path or one escaping the vault is a lint error (symlink into `results/<hid>/` if
your run dir lives elsewhere — the server follows symlinks by design).

**Enforcement (lint, not a wall).** `crux validate` errors when:
- `results/<hid>/` exists and holds ≥1 file but the node links no `.md` report;
- a linked artifact path does not resolve to a file in the vault;
- an artifact path is absolute or escapes the vault.

`crux close` still closes, but prints the same warning — a hypothesis with genuinely no
files must stay closable.

**Serving.** New read-only route `GET /file/<vault-relative-path>`: rejects absolute paths,
`..`, and dot-segments; allows an extension allowlist (`.md .txt .csv .tsv .json .png .jpg
.jpeg .gif .svg .webp .pdf`) declared once as `engine.SERVABLE_EXT` and keyed to content
types in `serve.FILE_TYPES`, so the UI can tell in advance what it may link; explicit
`Content-Type`; `Cache-Control: no-store`. Responses carry
`Content-Security-Policy: default-src 'none'; … sandbox` and `X-Content-Type-Options:
nosniff` — an SVG is the one allowlisted type that is *also a document*, and navigating
directly to one would otherwise run its script in the cockpit's origin, where
`/snapshot.json` is same-origin readable. Bodies are streamed, not buffered. No route
writes, ever — the cockpit's read-only invariant is unchanged.

**Rendering.** The right panel gains a **report reader**: click a `.md` artifact and the
pane renders it in full (headings, lists, tables, code, blockquotes, rules, images) with a
`← h1` back link. Images resolve relative to the report's own directory, through `/file/`.
Image artifacts render inline in the Artifacts list; anything else is a download link.

**And everywhere else.** `bodyOr()` — Problem, Idea/Hypothesis, Findings, Answer so far,
Detail, Goal — routes through the markdown renderer instead of escaped pre-wrapped text.
`[[wiki/…]]` citations keep working (the renderer already handles wikilinks). The renderer
gains an image rule and relative-link resolution; every fragment is still HTML-escaped
before markup is added.

### D · Full-screen panels
`state.pane ∈ {split, left, right}`, persisted under `crux-pane`, applied as
`body[data-pane]`. `left` = tree **or** wiki pane (whichever tab is up) takes the full
width; `right` = the detail pane does; the splitter hides in both. Controls: a `⤢` toggle
in the tree zoom cluster, one in the wiki zoom cluster, one beside the detail pane's text-
size control. Keyboard: `[` maximizes left, `]` maximizes right, `Esc` restores split
(ignored while typing in search). The tree refits after a mode change.

### E · Search bar
`flex: 0 1 230px` → `flex: 0 1 290px; min-width: 190px; max-width: 320px` — roomier, but
**bounded**: it must not grow to swallow the toolbar. The placeholder shrinks to fit inside
it (`Search nodes · ↵ jump`), with the full hint moved to the tooltip. Below 1400px the view
controls drop to icons (tooltips kept), which is what buys the box its width on a laptop
screen rather than collapsing it to the floor.

### F · Focus, reworked
Focusing a question **collapses every branch off its ancestor path** — the spine from the
root stays visible (so you keep your bearings), every sibling branch collapses to a `+`,
and the focused question's own subtree stays expanded. Nothing is deleted from the canvas.

- **Triggers:** double-click a node · the toolbar focus button when a node is selected · `f`.
- **Breadcrumb:** a chip over the tree — `root › q1 › q3 ✕` — ancestors clickable to focus
  one level up, `✕` (or `Esc`) to clear.
- The toolbar button becomes contextual: with a selection it reads `Focus q3`; with none it
  keeps today's `Focus open` behaviour; while focused it reads `Focused ✕` and clears.

### G · README
Every section, code block, table, and image stays exactly where it is. Prose gets ~35–40%
shorter: kill the repetition, the throat-clearing, and the long parenthetical asides. The
worked example and both sign-off beats survive.

### H · Update check — notify, never install
**crux does not update itself.** It reports that a newer release exists and hands over the
exact command for *this* install (`git -C <root> pull --ff-only` for a clone — resolved
through symlinks, since `install.sh` links the skills into one — or `npx skills update` for
a copied install), plus "ask your agent to update crux"; the `crux` skill documents the
preflight the agent must run first (clean tree, default branch, fast-forward only, never
stash/reset/force to make it apply).

*Rejected: auto-applying the update.* A research notebook records the engine version its
verdicts were produced under; an engine that rewrites itself in the background can land a
format change under a live vault with nobody deciding to. Updating stays a human act. An
engine bump against an existing vault keeps today's behaviour — the loud drift warning plus
a re-stamp — which is already the designed answer for reproducibility.

New `CRUX_VERSION = "0.5.0"` in `engine.py` — the *release* version, distinct from
`ENGINE_VERSION` (vault format). New stdlib-only `update.py`:

- Any CLI invocation may check GitHub's latest release **at most once per 24h**, cached at
  `$XDG_CACHE_HOME/crux/update.json` (else `~/.cache/crux/update.json`). The 24h window is
  **claimed before the request goes out**, so a failed or abandoned check still costs at
  most one attempt per day.
- The check runs in a **background thread with a ~1.5s timeout** and its result is written to
  the cache atomically (`os.replace`, so concurrent crux processes never read a torn file);
  the notice a user sees is printed **from the cache**, on **stderr**, so no command's output
  ever waits on the network or fails because of it. Offline is silent. The thread is
  deliberately *not* a daemon — a daemon dies when a short command exits, which would mean
  the answer is never recorded and the notice never appears; process *exit* may therefore
  wait up to the timeout, on the one invocation per day that checks.
- `CRUX_NO_UPDATE_CHECK=1` disables it entirely. The selftest runs with it set.
- The cockpit surfaces it too: `snapshot()` gains `crux_version` and an `update` block read
  **from the cache only** (`serve` never touches the network), and the topbar shows a small
  `update available → v0.6.0` chip when it says so.

Every decision-making part is a pure function (`parse_version`, `is_newer`, `should_check`,
`notice`) tested offline with an injected fetcher; the network call itself is never made
during tests.

### I · A question closes on an approved synthesis
The new close sequence, with two explicit human touchpoints:

```
review gate trips  →  crux synthesize "…" --for q3     # agent drafts the synthesis (s1)
                   →  PI reads it
                   →  crux approve s1                   # ◆ human approval, timestamped
                   →  crux answer q3 -t "…"             # ◆ now permitted; stamps synthesis: s1
```

- `cmd_approve(root, sid)` stamps `approved: <iso-8601>` on a synthesis node. Idempotent
  (the first approval's timestamp stands). Errors on a non-synthesis id.
- `cmd_answer(root, qid, …)` **refuses** unless some synthesis node lists `qid` in its
  `Related::` links *and* carries `approved`. The error names the exact three commands to
  run. On success the question's frontmatter gains `synthesis: <sid>` (deterministic pick:
  lowest id among approved).
- `--for` is added as an alias of `-q/--questions` on `synthesize`, so the single-question
  case reads naturally.
- **Migration / grandfathering:** questions already `resolved` in a pre-1.2 vault keep
  their status and are **not** flagged by `validate` — the gate applies to new `answer`
  calls only. This is what keeps every existing vault loading.

### J · The breath is gone
Delete the `BREATH` force from `TSIM`. The sim still warms for drags, fly-home, and
relayout glides — and now the rAF loop **stops completely** once cool, instead of running
forever to animate a wobble. A pointerdown on a node restarts it. Net effect: the tree is
perfectly still at rest and burns zero CPU there.

### K · Example vault (`segssl_vault`) refreshed to the new model
The bundled example is what `crux serve --dir …` and the README's 60-second path show, so
it has to demonstrate what v0.5 claims:
- `results/h1/` gains a real `report.md`, an SVG figure, and a PNG figure (the PNG proves
  binary serving), linked from h1's `## Artifacts`.
- Its four resolved questions get approved syntheses (created through the engine) so the
  close-gate is visible in the shipped example rather than only in the tests.

## Scope — what this does *not* do

- **No writes from the cockpit.** Read-only stays read-only; `approve`/`answer` are CLI/agent.
- **No new node types** and no change to the verdict derivation.
- **No artifact glyph on tree nodes** — node geometry is measured and delicate; artifacts
  surface in the detail pane only.
- **No seed-format artifact support** (`- artifact:` lines in a seed outline) — migration of
  existing result files stays manual for now.
- **No report generation.** crux links and renders reports; it never writes one.
- **No third-party dependency**, engine or frontend (the frontend keeps its single vendored
  `motion.js`; no markdown library — the hand-rolled renderer is extended).

## What the review pass changed

After the gate went green, the diff was read by four independent reviewers (security, PRD
conformance, backward-compat, frontend), and every finding was then handed to a skeptic
whose job was to refute it. Six survived; two were refuted with reasoning I agree with (the
wiki reader's "empty base" is the documented vault-relative convention, and the missing
Host-header check is not a delta of this change — a Host allowlist would break the
documented VS Code port-forward path). All six are fixed, with regression tests:

1. **`crux test --run` silently dropped every run link after the first** — a regression this
   change introduced. The insert point was chosen by a whole-body `_(none yet)_` probe, so
   adding a second section with a placeholder (`## Artifacts`) made it permanently true.
   Silent data loss, and the CLI still printed success. Appending is now scoped to the named
   section. **The suite missed this entirely** — it only ever passed `run=` once.
2. **`.svg` was active content at the cockpit's origin** — navigate straight to one and its
   `<script>` runs where `/snapshot.json` is same-origin readable. `/file/` now sends a
   restrictive CSP + `nosniff`; `<img>` rendering is unaffected.
3. **The update check re-hit the network on every command** — its 24h window was stamped
   only by a *successful* fetch, on a daemon thread that short commands killed on exit. The
   window is now claimed before the request; the worker is no longer a daemon.
4. **Cache writes were not atomic** (found via a flaky assert) — two concurrent crux
   processes could read a torn file and treat it as "we know nothing". Now `os.replace`.
5. **Artifacts the route can't serve were rendered as links that could only 404** — the
   servable set is now declared once (`engine.SERVABLE_EXT`) and the UI marks the rest inert.
6. **Review was a no-op while a report was open**; a manual expand while focused was undone
   by the next poll; the focus button kept a stale label. All fixed.

Two things were added beyond the original scope, both because the feature was incomplete
without them: an `inconclusive` hypothesis in the example vault (the new legend chip
otherwise pointed at nothing), and **synthesis visibility** — a resolved question links the
synthesis that closed it, and the synthesis renders its body and approval stamp, because
making synthesis load-bearing without a way to read it in the cockpit was a hole.

**Final:** 322 selftest asserts (baseline 203), stdlib-only, existing vaults load, engine
1.1 → 1.2 with migration proven, M1–M10 walked and signed off by the PI.

## Backward-compat / migration

Vault format changes (`## Artifacts` section, `synthesis:` on questions, `approved:` on
syntheses, the `results/` directory) → **`ENGINE_VERSION` 1.1 → 1.2**, with these proofs:

- a **copy** of `segssl_vault` re-stamped to `1.1` still runs `status` · `validate` ·
  `review` · a render · `snapshot` without error (drift warning expected, crash or wrong
  verdict is a fail);
- its four already-`resolved` questions stay resolved and unflagged (grandfathering);
- hypotheses with no `## Artifacts` section parse to an empty artifact list, not an error;
- `demo_vault` (the committed synthetic gate fixture) loads unchanged.
