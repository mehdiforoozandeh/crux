# PRD 16.1: Science voice — the invisible notebook

- **Kind:** feature   - **Spec:** [.spec/16-science-voice.md](../../.spec/16-science-voice.md)

## Problem / motivation

crux's agent-to-PI channel is ID-led and crux-first: the agent says "that's your open
question q1", "h1 → supported", "a synthesis awaits your approval". The PI is the advisor,
the agent is the grad student, crux is the grad student's notebook — and a grad student
does not tell their advisor "q19 is solved".

Three artifacts *teach* the wrong voice by example (SKILL.md's session dialogue, README's
transcript, the situate eval's gold answer) and two mechanisms *enforce* it
(`crux-situate`'s "name the ids in the first line" mandate, and `situate:unanchored`, which
fails an answer whose first line does not name the anchor ids). Spec 16 records the full
argument; this PRD carries the whole epic through the gate in one change, because the
pieces interlock: the lint cannot change without the agent definition, and neither holds
without the eval that pins them.

## Design decision

Six rules, one deterministic scanner, one engine relaxation, one engine addition, and a
re-authoring of every artifact that models the old voice.

### 1. The mirror rule, as code (`engine.voice_lint`)

A new pure function beside `situate_lint`. Input is an ordered conversation
`[(speaker, text), …]`; output is `(id, message)` findings, empty when clean.

- **`NODE_ID_RE = re.compile(r"\b[qhts]\d+\b")` — case-sensitive, and that is measured.**
  Over all four shipped example vaults (3,016 matches across 394 real ids) the
  lowercase-only form produces **zero** non-id matches. Adding uppercase introduces exactly
  the false positive spec 16 predicted: `T5`, the model, in
  `scaling_vault/wiki/transformer-language-models.md`. Uppercase is therefore excluded, the
  same way spec 14 settled its matcher by measurement rather than by argument.
- **`CRUX_LEXICON`, a frozenset** — the home spec 16 names as the default, beside
  `GLOSSARY_STOPLIST`. Membership was decided by counting each candidate in the example
  vaults' **literature prose** (`wiki/`), which is pure science voice by the wiki's one-way
  flow rule. Candidates with real hits there are **excluded** as measured false-positive
  risks: `seed` (19 — random seeds), `partial` (5), `anchor` (4), `idea` (4), `tree`
  outside notebook context, `parent` (2). `brief` and `pursue` are excluded as plain
  English on their face. Plain science words — question, hypothesis, evidence, finding,
  experiment, check, result, supported, refuted — are free, per the spec.
- **Licensing.** Walking turns in order: a term or id the **PI** used is licensed from that
  turn on. Terms in the vault's `glossary.md` `## Terms` are licensed from turn zero — the
  permanent graduation path. Ids are licensed for the conversation only, which the
  per-conversation scan gives for free.
- **Notebook mode.** A PI turn using a notebook-surface term (`notebook`, `tree`,
  `cockpit`, `vault`, `graph`) licenses **node ids** for the agent turns that follow it,
  until the next PI turn. Deterministic, and it needs no new marker in the transcript.

### 2. `situate:unanchored` accepts the anchor's title **or** its id

An anchor becomes `"q20"` or `("q20", "how do we cut the label budget")`; the finding fires
only when *neither* form appears (title matched verbatim, case-insensitively). The
deterministic misresolution check spec 13 bought stays; ids stop being forced into chat.
`crux brief --lint-situate` gains `--anchor-title`; the eval oracle reads the title from the
fixture vault.

### 3. Relevance gate, engine-computed (spec 09 rule 1, the spec's stated default)

`crux review --json --near <id>` and `crux task review --json --near <id>` annotate each
pending gate with `relation` ∈ {`self`, `ancestor`, `descendant`, `sibling`, `unrelated`}
and `in_scope` (relation ≠ `unrelated`). The engine states the fact; the agent's rule —
never raise an out-of-scope gate on its own initiative — is in SKILL.md. Nothing is
filtered out: a PI who asks "what's pending" gets everything.

### 4. CLI text output declared agent-facing

Second person → third person throughout `crux.py`, including the module docstring, which
argparse prints as `crux --help`. No other CLI text change; the channel stays ID-led.

### 5. Glossary graduation actually works

`glossary_candidates` waives the centrality filter for a term in `CRUX_LEXICON`. Without
this a crux process term can never be proposed, because it appears nowhere in the vault
corpus the filter counts — the graduation path spec 16 relies on would be dead on arrival.
The proposal still comes from the orchestrating agent (crux-glossary is excluded from the
conversation by construction, and PI usage is a conversation fact), and the PI still signs
with `crux glossary accept`.

### 6. Artifacts re-authored

`skills/crux/SKILL.md` (new top-level **voice** section carrying rules 1–6, plus the
session dialogue, gate prose and lifecycle snippets), `README.md`'s transcript,
`agents/crux-situate/AGENT.md` (title-first anchoring), and the three situate eval
submissions plus the manifest's reference answer.

### 7. The persona eval — a permanent fixture class

`skills/crux/evals/fixtures/persona-01/`, joining spec 10's harness and obeying its
architecture: **the harness never invokes an agent.** A submitted transcript is scored.
- **Vault:** the shipped `scaling_vault`, referenced by a new manifest field
  `example_vault:` rather than copied, so the fixture cannot drift from the real example.
  Chosen because it is 13 nodes, deliberately jargon-free (the persona needs no field
  knowledge), and its `q3` already holds one in-flight run and one untested idea — the
  states a signature-gate conversation needs.
- **Layer 1, deterministic:** `voice_lint` over the transcript's agent turns → a **hard
  check** beside the band, like situate's lint.
- **Layer 2, vault state:** the manifest declares `state:` predicates; the submission
  carries `vault_after` (a captured `crux status --json`). Also a hard check.
- **Layer 3, the judge:** the planted ids are the **soft** behaviors only — gates phrased
  as science questions, the relevance gate honored, the draft shown at signature, the
  cockpit offered. `ground_truth: proxy`, since a judge is a proxy and spec 10 requires
  that be admitted rather than dressed up.
- Three canned submissions ship: a clean one, a **mirror-rule positive** (the persona types
  an id; the agent's reuse must not be flagged), and a **notebook-mode** one.
- `band: unset`. Spec 10 left bands to the PI; so does this.

**Main alternative rejected:** judging the voice with an LLM alone. A regexable property
graded by a model is a property that silently stops being checked; and spec 16's own
rejected-alternatives list settles that a one-off run lets the next prompt edit regress.

## Scope

Does **not** touch the cockpit (ID badges stay — the cockpit *is* the notebook), does not
add a `crux voice` CLI verb (the scan's consumers are `evals.py` and `selftest.py`), does
not change any vault format, and does not re-verdict or migrate any node. The other nine
agents keep ids in their reports; the voice rules bind at the relay point.

## Delivered beyond the PRD, and why

- **`evals.py --project-state`** — reads `crux status --json` on stdin and prints the
  projection a persona submission carries as `vault_after`. Added because the alternative is
  a submitter hand-writing the end state, which is how a state assertion quietly becomes a
  wish.
- **A row in spec 10's proxy register** for `persona-01`, plus a sentence saying the table is
  a live index rather than a 10.4 artifact. `selftest` diffs the register against the fixture
  tree both ways, so a new fixture *must* appear there — the assert is the reason, not an
  afterthought.
- **`agents/crux-glossary/AGENT.md`** gains one rule: crux's own vocabulary is proposable,
  but not by that agent — what licenses a term is the PI *using* it, which is a conversation
  fact, and the conversation is exactly what crux-glossary is excluded from.
- **Five spec-10 asserts rewritten from `== "3.1"` to `>= 3.1`.** They claimed "spec 10 did
  not move the stamp"; written as equality they instead claimed "the stamp has never moved
  since", which this PRD falsifies. `at_least_version`'s own docstring predicted this exact
  failure.

## Backward-compat / migration

No vault format change. `ENGINE_VERSION` **is** bumped 3.1 → 3.2 because a shipped
deterministic bound (`situate:unanchored`) changes behavior, and the stamp is how a vault
records which engine wrote it. Proof required: a vault stamped 3.1 loads, validates and
renders identically under 3.2, with the drift warning expected and no crash or verdict
change.
