# PRD: 05.1 — the git and workspace layer

- **Kind:** feature
- **Spec:** [.spec/05-autopilot.md](../../.spec/05-autopilot.md) — 05.x series, after [05.0](05.0-flight-plan-and-brief.md)

## Problem / motivation

05.0 built the pure half of autopilot — the plan the PI signs, the lineage field, the selection
arithmetic, the brief. None of it starts a process, so none of it can yet give an attempt a
place to run. This PRD is **the impure half, and still not the loop**. It builds the five
mechanisms every attempt needs: a git worktree cut from the parent attempt's commit, a reference
that keeps that commit after the worktree is gone, a centrally reserved node id, a workspace
named by that id, and a manifest that catches writes git cannot see. It also extends 05.0's
`crux auto check` to do the one thing a static validator cannot — run the frozen scorer once
and confirm the objective resolves in its output. Each is a collision or a containment risk, and each is testable in
seconds against a throwaway git repository. The line that governs the slice is **D19**:
`engine.py` stays pure, so every process, git and concurrency call lands in a new module,
`skills/crux/scaffold/autopilot.py`, which imports the engine and is never imported by it.

## Design decision

### A · The repository is discovered, and named only when discovery is wrong

A crux vault often sits inside the project it records (`<repo>/cruxvault/`), so the repository
root is normally derivable. The flight plan gains an **optional** `repo:` field: absent, the
repository is `git -C <vault> rev-parse --show-toplevel`; set, it is that path, and a `repo:`
that is not a git working tree is reported by `auto check`. When neither yields a repository,
`auto check` reports it and skips every later git check rather than guessing. The field is
optional because every 05.0 plan must keep validating, and `git` is asked rather than the tree
walked for a `.git` entry because `git` already knows about linked worktrees, `.git` files and
ceiling directories.

**Rejected: `repo:` required on every plan.** It breaks every plan 05.0 wrote, to restate
something the vault's own location already says.

### B · The scorer prints one JSON object, and the driver writes it

The scorer's contract is one sentence: **standard output carries exactly one JSON object, the
metrics document, and nothing else; everything a human reads goes to standard error.** That
object has the shape `results/<hid>/metrics.json` already has — leaves are objects carrying
`value` — so the objective `address::` from 05.0 resolves inside it through `resolve_address`,
unchanged. The driver writes the object it received to `results/<hid>/metrics.json` verbatim;
the engine never writes that file, it only reads it. This is D9 made concrete: the number comes
from the command's output, so a worker that rewrites a metrics file on disk rewrote nothing
that counts.

Four failures, each named: the command cannot start or exits non-zero → `scorer-exit`, with a
bounded tail of stderr; it runs past `scorer_timeout:` (optional, default 600 seconds) →
`scorer-timeout`; its stdout is not exactly one JSON object → `scorer-output`; the objective
address does not resolve inside that object, or resolves to something that is not a number →
`scorer-address`.

`crux auto check` runs the scorer once on the current code, in the repository root, and fails on
any of the four; `crux auto check --static` keeps 05.0's behaviour exactly — engine only, no
process — for a PI editing a plan. The scorer is invoked through `shlex.split` with no shell and
gets exactly two environment variables, because it must be able to find what the run produced
and a third is a contract nobody asked for: `CRUX_ATTEMPT` (the attempt id, the baseline's
during a dry run) and `CRUX_WORKSPACE` (its workspace, a throwaway directory during a dry run).

**Rejected: scanning stdout for the last line that parses as JSON.** It silently prefers a log
line that happens to be JSON over the real document, and fails as a wrong number rather than an
error.

**Rejected: the agent-command reachability check.** The spec's `auto check` line names it beside
the scorer, but the agent command template, its `{brief}` substitution and its failover walk are
all defined in **05.3**, so a probe built here is rewritten there. That third of the acceptance
line is 05.3's, and is recorded as such.

### C · One vault-level lock, taken for short critical sections

The two operations §7 forbids running in parallel — node id allocation and index regeneration —
both write **vault-level** files: the counter in `.crux.yaml`, and `META.md`, `EXPERIMENTS.md`,
`TASKHUB.md` at the vault root. A lock under `auto/<qid>/` cannot protect them, because two runs
in one vault have two such directories and one counter. The lock is one file at
`<vault>/auto/.lock`, taken by `os.open(path, O_CREAT | O_EXCL | O_WRONLY)`, released by
`os.unlink`, holding JSON: pid, hostname, an ISO timestamp, the operation name. Acquisition
polls every 50 ms up to 60 seconds, then raises naming the holder's pid and the lock's age. A
lock is stale, and reclaimed once, when its recorded host is this host and its pid is not alive,
or when its age exceeds 900 seconds; a lock from another host is reclaimed by age alone.

It serializes four things: id reservation, `refresh` and the index write, the `reserved.json`
update, and — from 05.2, whose paths 05.0 fixed — writes to `state.json` and `ledger.jsonl`. A
worktree, a workspace and a manifest are each named by an already-unique attempt id, so none of
them needs it.

**Rejected: `fcntl.flock`.** It is POSIX-only, and it leaves nothing on disk a human can read,
so a lock nobody holds cannot be told from a lock somebody holds.

### D · A reserved id is recorded before its node exists

Reservation takes the lock, calls the engine's existing `_new_id`, records the id, releases. The
record is `auto/<qid>/reserved.json`: an object mapping the id to its time, reserving pid,
island, parent attempt, and a state of `reserved`, `materialized` or `abandoned`. The counter
alone already prevents two callers getting one id; the record exists for the case it cannot
describe — an attempt that died between reservation and the worker writing its node. Without it
a resumed run cannot tell an id it must not reuse from an id never handed out.

**Rejected: writing a placeholder node at reservation time.** A half-written idea node is a
node: it enters the tree, the roll-up, the review gate and `crux validate` immediately, so
every attempt that dies early leaves a permanent malformed hypothesis in the science tree.

### E · Refs, branches and worktrees

An attempt is a commit under `refs/crux/auto/<qid>/<hid>` (D7). Around it:

| name | what it is | created by 05.1 |
|---|---|---|
| `refs/crux/auto/<qid>/base` | the commit the run starts from | yes, at run open |
| `refs/crux/auto/<qid>/<hid>` | one attempt's commit | yes, when the attempt is recorded |
| `crux/auto/<qid>/run` | the run branch | yes, at run open |
| `crux/auto/<qid>/island/<island>` | one per declared island; moving it forward **is** the island-best pointer move | yes, at run open, at the base commit |
| `main` | the PI's, and only the PI's | never |

`run` and `island/…` are siblings rather than `crux/auto/<qid>` plus `crux/auto/<qid>/<island>`,
because git cannot hold a reference that is also a directory of references; `base` is not a
valid hypothesis id, so it cannot collide with an attempt.

A worktree is created per attempt, `git worktree add --detach <path> <parent commit>`, the
parent commit being the parent attempt's ref or `base` for an island's first attempt. It lives
at `<git common dir>/crux-auto/<qid>/<hid>` — inside `.git/`, so it is never scanned by the
project's tooling, matched by a glob or committed by accident, and it goes when the clone goes.
Once the commit is recorded into its ref the worktree is removed; the ref keeps the commit
reachable, which is the whole reason attempts are refs. No per-island worktree is created: the
per-attempt one already gives §7 the separation it asks for.

**Rejected: worktrees in a sibling directory beside the repository.** It puts run state outside
what a user backs up and clones, and two clones of one project collide on one path.

### F · Three path sets, and an attempt may write to one

The plan already declares `frozen:` and `writable:`. This PRD fixes what they mean at run time.

- **Frozen** — repository-relative paths a worker's commit may not touch, detected by
  `git diff --name-only <parent commit> <attempt commit>`. The **effective** frozen set is the
  plan's `frozen:` plus the vault's own path when the vault lies inside the repository, so a
  worker cannot commit an edit to the notebook that records its verdict.
- **The workspace** — `<W>/<hid>/`, where `W` is the first entry in `writable:`, resolved against
  the repository root rather than the worktree. The one place an attempt writes freely; the
  template lists `work/` first for this reason.
- **Shared roots** — everything under any `writable:` root that is not this attempt's workspace.
  Watched by the manifest, never written by a well-behaved attempt.

The driver's write of `results/<hid>/metrics.json` is a **vault** write in the vault's own
checkout, not a repository write in a worktree, so it is outside all three sets.

**Rejected: a new `workspace:` frontmatter field.** The path is derivable from two fields the
plan already carries, and a fourth path field is a fourth way for a plan to contradict itself.

### G · The manifest is a before-picture of the shared roots, and retention spares the record

`auto/<qid>/manifests/<hid>.json`, written before the run: the roots, the workspace excluded from
them, and one entry per file — path, size, `mtime_ns`. The walk does not follow symlinks, so a
symlinked dataset is recorded as a link and not traversed. After the run the same walk is
compared and every difference is reported as `added`, `removed` or `changed` with its path,
appended to the same file with the time of the re-check. This catches the write to a shared
scratch or dataset directory git cannot see (D10). 05.1 **detects and reports**; the verdict
that follows is 05.2's.

`retention:` takes `all` (every workspace kept), `failed` (kept for an attempt that closed
`refuted` or `invalid-run`, deleted for one that closed `supported` — the template's default:
keep what there is something to debug), or `none` (every workspace deleted).

Deletion covers the attempt's workspace directory and nothing else. An attempt's ref, its node,
its `results/<hid>/metrics.json` and its manifest survive every setting. Worktrees are removed
in every setting, as soon as the commit is in its ref.

### H · `promote` is the PI's verb, and the only new one that writes

`crux auto promote <hid> [--branch <name>]` creates a branch at the commit named by
`refs/crux/auto/<qid>/<hid>`, defaulting to `crux/auto/<qid>/promoted/<hid>`. It does not check
out, does not merge, and never touches `main`. It refuses an unknown id, an id with no ref in
this run's namespace, an id outside the plan's anchor, and a branch name already in use. Beside
it one read-only verb, `crux auto refs`, lists the run's refs and worktrees with their commits
and attempt ids. Everything else built here is a function in `autopilot.py` whose only caller is
05.2's loop, tested in selftest — a verb whose only caller is a loop is a surface with no user.

**Rejected: a verb per object (`auto worktrees`, `auto manifest`).** Three verbs answer one
question, "what does this run own right now", and spec 06 settled that shape as selectors on
fewer verbs.

## Scope — what this does not do

- **No loop.** Nothing selects, launches, retries, budgets or resumes; every function built here
  is called by 05.2. **No agents** — worker, steward, agent command and reachability probe are
  05.3. **No cockpit** (05.4) and **no leash change** (05.2).
- **No verdict closes.** Frozen-path and manifest violations are **detected and reported**; the
  `invalid-run` close is 05.2's, with the retry rule that a crash is not a refutation.
- **No `state.json` or `ledger.jsonl` writes.** Their paths were fixed in 05.0 and the lock that
  will guard them is defined here; neither file is written.
- **No `crux validate` change** — a reserved id that never became a node is recorded, not linted.
- **No sandboxing.** Containment is the run command's, per §10, and **`main` is never written**
  by any operation in this slice.

## Acceptance criteria

- [x] `auto check` fails, naming `scorer-exit`, when the scorer cannot start or exits non-zero,
      and the message carries a bounded tail of its stderr.
- [x] `auto check` fails, naming `scorer-output`, when the scorer's stdout is not one JSON object.
- [x] `auto check` fails, naming `scorer-address`, when the objective address does not resolve to
      a number inside the scorer's output.
- [x] `auto check` passes on a plan whose scorer prints a metrics object in which the objective
      address resolves to a number, in a git repository the test creates.
- [x] `auto check --static` starts no process and returns what 05.0 returned, asserted by a test
      that fails if a subprocess is spawned.
- [x] `auto check` fails, naming `repo`, when the vault has no enclosing git repository and the
      plan sets no `repo:`, and it attempts no git operation afterwards.
- [x] A 05.0 plan carrying neither `repo:` nor `scorer_timeout:` validates unchanged.
- [x] The driver writes `results/<hid>/metrics.json` with the exact object the scorer printed,
      and a static scan finds no write to that path in `engine.py`.
- [x] Twenty ids reserved by four concurrent processes against one temp vault are all distinct,
      and every one appears in `auto/<qid>/reserved.json`.
- [x] A reserved id whose node is never written stays recorded `reserved`, is never handed out
      again, and leaves the vault validating clean.
- [x] A second acquirer of a held lock fails after the stated wait, naming the holder's pid.
- [x] A lock whose recorded pid is dead on this host is reclaimed once, and the reclaiming caller
      acquires it.
- [x] Recording an attempt creates `refs/crux/auto/<qid>/<hid>` at the worktree's HEAD commit,
      and that ref still resolves to the same commit after the worktree is removed.
- [x] An attempt's worktree is cut from its parent attempt's commit, and an island's first attempt
      from `refs/crux/auto/<qid>/base`.
- [x] Opening a run creates the run branch and one island branch per island at the base commit,
      and no created branch name is a prefix-directory of another.
- [x] A worker commit touching a path in the effective frozen set is reported as a frozen-path
      violation naming the path, and no 05.1 code closes the attempt.
- [x] The vault's own path is in the effective frozen set when the vault lies inside the
      repository, so a commit touching the vault is a frozen-path violation.
- [x] The manifest re-check reports a file created under a shared root as `added` and a file
      changed there as `changed`, reports neither for a file inside the attempt's own workspace,
      and re-checks clean over untouched roots.
- [x] `main` resolves to the same commit and the main working tree stays clean across open,
      reserve, worktree, commit, record, manifest, retention and promote.
- [x] `auto promote` creates a branch at the attempt ref's commit, and refuses an unknown id, an
      id with no ref, and a branch name that already exists.
- [x] `retention: none` deletes the workspace, `all` keeps it, `failed` keeps it for a refuted
      attempt and deletes it for a supported one — and no setting removes the ref, the node, the
      metrics file or the manifest, or leaves a worktree behind.
- [x] A static scan finds that `engine.py` imports no impure module and names no git command,
      that `autopilot.py` imports only standard-library modules and `engine`, and that `engine`
      imports `autopilot` nowhere.
- [x] `auto promote` and `auto refs` emit parseable JSON under `--json`, and `auto check --json`
      keeps every key 05.0 emitted.
- [x] A vault with no `auto/` directory loads, validates and renders unchanged under this engine,
      with only the usual drift warning.

## Backward-compat / migration

**No vault format change, so `ENGINE_VERSION` does not bump.** Everything this slice writes lives
under `auto/` — the lock, `reserved.json`, `manifests/` — and none of it is a node, is read by a
view, or enters a verdict or a roll-up. The two new flight-plan fields, `repo:` and
`scorer_timeout:`, are optional, and a plan is not a node either. The gate's rule is unchanged:
the bump comes in 05.2, where an attempt closes on a derived verdict.

No migration. A vault written before this release has no `auto/` directory, which is the normal
case rather than a defect, and a vault carrying a 05.0 plan validates through the same 16 static
checks it always did. One 05.0 criterion is **superseded and re-pointed**, not dropped:
"`crux auto check` starts no process" now holds for `crux auto check --static`, and its selftest
assertion moves to that flag. The default `auto check` deliberately starts one process, which is
the point of this slice.
