# PRD: 05.0 — the flight plan and the brief

- **Kind:** feature
- **Spec:** [.spec/05-autopilot.md](../../.spec/05-autopilot.md) — first of the 05.x series

## Problem / motivation

Spec 05 is unparked: crux should be able to run one anchor question unattended. That epic
needs processes, git worktrees and concurrent runs, none of which the engine has ever done —
`engine.py` never shells out, never touches git and never threads, and that purity is what
makes it testable without a cluster.

So the epic splits at that seam, and **this PRD is everything on the pure side**. It builds
the contract the loop will later execute: the file the PI signs, the field that records
lineage, the arithmetic that picks what to try next, and the briefing handed to each worker.
No process is started here and no git command is run.

Doing this first is deliberate risk order. The schema and the brief are what every later
slice depends on, they are wholly testable with no model, no GPU and no network, and getting
them wrong is expensive to discover at two in the morning on attempt 140.

## Design decision

### A · The flight plan is a crux document, not a config file

`engine.yaml_load` is **flat**: `key: value` pairs, no nesting, no indentation, no lists.
The flight plan has nested content — checks with kinds and failure scenarios, several budget
axes, a list of islands — so a naive design would either need a real YAML parser (which the
standard library does not have, and which we would then have to test) or JSON (which no other
human-facing crux file uses).

**Neither is necessary.** The flight plan is written as an ordinary crux document —
frontmatter plus markdown sections — at `auto/<qid>/plan.md`:

- **frontmatter** carries the flat machine fields: mode, island cap, budget axes, parallelism,
  retries, retention, the scorer and run commands, the agent command and its failover, the
  frozen paths and writable roots as comma-separated lists, exactly as `task_categories`
  already is in `.crux.yaml`.
- **`## Goal`** — one falsifiable sentence.
- **`## Objective`** — the metrics address, the direction, the success bar.
- **`## Null`** — the PI-approved boring explanation.
- **`## Verifiables`** — **parsed by the existing `_verifiables()` and
  `verifiable_scenarios()`**, so kinds, failure scenarios and the combination rule need no new
  format and no new parser.
- **`## Guidance`** — appended to, never overwritten, each entry stamped with a time and an
  author.

This is the reuse that makes the slice small: the one genuinely nested part of the plan is
already a format crux parses, and the flat remainder fits the loader that exists.

Two sibling files, both written later in 05.2 but whose paths are fixed here so nothing has
to move: `auto/<qid>/state.json`, rewritten whole after every attempt, which is how ERA makes
a search inspectable mid-flight and resumable after a crash; and `auto/<qid>/ledger.jsonl`,
appended one line per event, which is how Weco logs a run whose steps finish out of order.

### B · `builds_on:` records lineage without bending the tree

An idea node gains an optional `builds_on: <hid>` naming the attempt it was branched from.
It is the bandit's parent link and the cockpit's edge. The tree itself is unchanged:
attempts stay flat siblings under their island question, because tree depth must track
questions rather than iteration count.

Validation: the target must exist, must be an idea, must sit under the same question, and
the graph must be acyclic.

### C · Selection is arithmetic, so it lives in the engine

Flat PUCT over an island's attempts is a pure function of vault state: rank score plus an
exploration bonus that decays with visits, ancestor visits back-propagated. It is ported
from ERA's `futs.py` rather than invented, including the `1/N` prior, which is load-bearing —
a constant prior makes exploration grow without bound and never settle.

`c_puct = 0` is Climb. There is no separate greedy code path.

Virtual visits, which count an in-flight attempt as if it had reported, are implemented here
as an argument to the selection function even though nothing runs concurrently until 05.2.
The alternative is changing the signature later, once callers exist.

### D · The brief is assembled and then checked by code

Assembly follows `brief()`: a pure read, byte-stable. The six checks from the spec are
implemented as part of assembly rather than as a separate linter, so a brief that fails one
is never produced, not merely reported on.

The check that carries the most weight is the fifth: every number in the brief resolves to a
live vault address, reusing the contract behind `crux deck --verify`. Without it the brief
can carry a stale "current best" that no reader would catch.

**Rejected: JSON for the flight plan.** It parses for free but it is the only human-facing
crux file that would not be markdown, and the PI has to read and amend this one.

**Rejected: a general YAML parser.** A feature is not a reason to acquire a parser and a
test suite for one, and the nested part of the plan is already a format crux reads.

**Rejected: writing selection in the new module.** It is arithmetic over vault state with no
side effects, so it belongs where it can be tested without a repository.

## Scope — what this does not do

- **No process is started.** No scorer dry-run, no agent invocation, no run command. The
  `crux auto check` shipped here validates the plan statically and stops; 05.1 extends it to
  execute the scorer once.
- **No git.** No worktrees, no references, no commits, no promotion.
- **No loop.** Nothing selects and then acts; selection is a function this PRD leaves
  uncalled except by tests.
- **No agents.** `crux-auto-worker` and `crux-auto-steward` arrive in 05.3.
- **No cockpit.** The tab is 05.4. No snapshot key is added yet.
- **No leash change.** The ruling that attempts close without a per-attempt signature is
  written into `SKILL.md` in 05.2, where something can actually close an attempt.

## Acceptance criteria

- [ ] A plan missing any required frontmatter field is refused, and the message names the
      field.
- [ ] A plan whose `## Verifiables` carry no outcome-neutral control is refused.
- [ ] A plan whose objective address does not correspond to a check that discriminates
      against the declared null is refused.
- [ ] A plan whose objective address does not resolve in the metrics tree is refused.
- [ ] A plan whose frozen paths and writable roots overlap is refused.
- [ ] `## Verifiables` in a plan parses to the same structure as the identical section on a
      node, asserted by comparing the two parses.
- [ ] `## Guidance` entries are append-only: a second write preserves the first verbatim, and
      each entry carries a timestamp and an author.
- [ ] `builds_on:` pointing at a missing node, a non-idea, a node under a different question,
      or forming a cycle is reported by `crux validate`.
- [ ] A node with no `builds_on:` validates exactly as it does today.
- [ ] Selection with `c_puct = 0` returns the highest-scoring attempt on every call.
- [ ] Selection reproduces `futs.py`'s ranking on a fixture of scores, asserted against
      values computed from the vendored formula.
- [ ] A virtual visit changes which attempt selection returns, on a fixture built so that it
      must.
- [ ] Assembling the same brief twice over an unchanged vault yields byte-identical output.
- [ ] An assembled brief contains no substring of the anchor's `## Problem Statement`.
- [ ] An assembled brief contains nothing from a sibling island except that island's best.
- [ ] Assembly fails, naming the slot, when a required slot is absent or empty.
- [ ] A section over its budget is truncated by the declared rule, and the brief states that
      truncation happened.
- [ ] Every number in an assembled brief resolves to a live vault address; a brief carrying a
      stale best is rejected by the same check.
- [ ] A brief whose island has no refuted siblings says so explicitly rather than emitting an
      empty section.
- [ ] `crux auto brief <hid> --lint` prints the brief and the result of every check above,
      and exits non-zero on any failure.
- [ ] `crux auto check` validates a plan and exits non-zero on a bad one, without starting any
      process (asserted by a test that would fail if a subprocess were spawned).
- [ ] Every new verb supports `--json`.

## Backward-compat / migration

**Yes, the vault format changes** — `builds_on:` is a new optional field on idea nodes, so
`ENGINE_VERSION` bumps.

The change is additive and needs no migration. A vault written before this release carries
the field nowhere, and its absence is the normal case rather than a defect. Existing vaults
load unchanged and show only the usual drift warning, which is the bar every spec since 06
has had to clear.

`crux migrate` gains nothing here: there is no old shape to rewrite.
